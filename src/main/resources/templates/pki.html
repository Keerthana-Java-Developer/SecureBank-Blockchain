SECURITY CENTER

Security & PKI

Security features available in this Java banking demo.

🔐

Password Hashing

BCrypt password hashing helps protect stored passwords. Original passwords should never be stored as plain text.

#

SHA-256 Ledger Integrity

Transactions store a SHA-256 hash and a reference to the previous transaction hash. Ledger verification must also recompute hashes to detect changes to transaction data.

✓

Transfer Validation

The application checks transfer amounts, recipient details, self-transfers and available balance.

🛡️

CSRF Protection

Spring Security CSRF protection is enabled. Every POST form must include a valid CSRF token.

🔑

RSA & Private Keys

RSA key generation is demonstrated in this project. Private keys must be protected and must not be exposed in webpages or logs.

Project Security Notes

This is an educational banking application, not a production banking system. Production use requires additional controls, including proper authorization, secure session management, OTP expiry and attempt limits, protected private-key storage, and comprehensive audit logging.

Hash-linked transactions demonstrate tamper-evident ledger concepts. They do not, by themselves, create a distributed blockchain network.
